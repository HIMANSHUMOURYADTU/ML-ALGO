    03 The constraint

    Nothing from after the order leaves the counter.

    The target is delivery_minutes. It is never an input. Identifiers are dropped too: order_id would not generalise, and restaurant_id would let the model memorise a venue instead of learning how delivery works.

    1. 01

      Order arrives

      Cuisine, zone, distance, basket, courier, weather, and the placement timestamp. That is the whole world the model is allowed to see.

    2. 02

      Clock becomes features

      The raw timestamp is replaced by hour, weekday, month, weekend, lunch rush, dinner rush, and a combined rush flag.

    3. 03

      Pipeline learns on train only

      Median for missing numbers. The token “Unknown” for missing weather. Standardise numbers. One-hot encode categories, ignoring unseen labels at test time.

    4. 04

      Three hundred shallow trees

      Each tree is depth 3 and is fit to the residual. The learning rate of 0.05 keeps every correction small.

    5. 05

      One number per order

      After selection, the same pipeline is refit on all 8,000 labelled orders and scored on 2,000 unseen ones.

    04 Feature engineering

    A timestamp is a set of delivery conditions.

    Rush windows follow the notebook exactly. Lunch is hour 12 through 14. Dinner is hour 18 through 21. Weekend is Saturday and Sunday. The original clock column is not passed to the model.

    2025-03-01 18:42

    hour 18 Saturday March weekend dinner rush rush hour

    Median for numbers

    329 training orders are missing courier_trips_completed. The median is learned inside the pipeline, so the validation fold never leaks into the fill value.

    “Unknown” for weather

    228 training rows and 51 test rows have no weather. Filling with a real category would invent a sky. A dedicated missing token keeps that fact visible.

    05 Model selection

    Keep a change only when the held-out minute gets smaller.

    An 80/20 split with random_state=42 holds out 1,600 orders. Mean absolute error is the metric, because the unit is already the thing a customer feels: minutes.

    Not kept

    Hand-built interactions

    Items × prep, distance × rush, and distance × prep looked reasonable and even ranked high in a tree. Ablation said otherwise. Dropping them moved validation MAE to 3.35345.

    Not kept

    PCA on the basket

    Items and subtotal were compressed to one component. Validation MAE rose to about 3.4733, and the features became harder to read. The original columns stayed.

    Not kept

    The tuned grid

    5-fold search preferred learning rate 0.08, depth 2, 400 trees, subsample 1. Cross-validation MAE was 3.51194. On the same held-out set it scored 3.36462 — a little worse than the original, so the original stayed.

    08 Where the average hides

    A 3.35 minute MAE still misses a 137 minute order.

    Validation order 702403 actually took 137 minutes. The model predicts 30.1. The trip is only 2.6 km, prep is 13.3 minutes, the vehicle is a scooter, and the weather is heavy rain at noon. The trees stay near an ordinary delivery, because nothing in the allowed features looks like a two-hour trip. Average error and the worst order are different questions.
